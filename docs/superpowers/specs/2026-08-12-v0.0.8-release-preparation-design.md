# RestfulToolkit v0.0.8 发布准备设计

## 目标

在不改变扩展功能、不升级依赖、不操作 Git 历史或远程 Marketplace 的前提下，生成可由维护者手动上传的 `restful-toolkit-0.0.8.vsix`，并确保代码、测试、OpenSpec 与用户文档对 v0.0.8 的描述一致。

## 发布口径

- 正式版本：`0.0.8`
- 正式发布日期：`2026-08-12`
- 变更范围：合并 2026-07-29 至 2026-08-12 已完成的解析、扫描、搜索、Base URL、watcher 与 Marketplace 统计维护改动
- 发布方式：本地生成并验证 VSIX，由维护者手动上传 Marketplace
- 明确排除：依赖升级、功能扩展、OpenSpec 归档、Git 暂存/提交/推送、Marketplace 自动发布

## 调整内容

1. 将 `CHANGELOG.md` 的 v0.0.8 日期统一为 2026-08-12，并保持中英文条目属于同一个版本段。
2. 将文档清单中的两条 v0.0.8 历史记录合并为单条正式发布记录。
3. 逐项核实现有 Copy URL/cURL OpenSpec；为缺失的命令编排路径补充回归测试后，再同步任务完成状态。
   多路径 Spring mapping 的复制命令稳定采用源码中第一个声明路径，端点扫描仍拆分全部路径。
4. 将 `vscode:prepublish` 对齐到 Webpack 生产构建，并收紧 `.vscodeignore`：发布包只保留 `dist/extension.js`、扩展清单、国际化、图标、许可、README 与 CHANGELOG，排除模块化编译产物、开发依赖、本地 Agent 资料、测试和构建配置。
5. 依次运行编译/lint/单元测试、专项脚本、生产构建、OpenSpec 严格校验、VSIX 打包和包内容检查。

## 异常处理

- 测试或构建失败时停止打包并修复当前范围内问题。
- OpenSpec 仓库级历史告警与本次 change 无关时如实记录，不扩大范围修改。
- VSIX 工具需要在沙箱外启动子进程时，仅请求打包与只读包检查所需权限，不执行发布。
