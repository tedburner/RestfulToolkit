## 为什么

RestfulToolkit 当前会等待首次工作区扫描完成后才结束扩展激活；它还会为不含 Controller 的文件执行不必要的解析，并且在受监听文件不再声明任何端点时残留旧缓存。端点数量较大时，现有的有序数组 top-K 搜索和不受限的初始 QuickPick 数据构造也会越来越昂贵。

本次变更将在保持纯内存生命周期的前提下提升响应速度与索引正确性：端点索引和扫描元数据均不会持久化到磁盘。

## 变更内容

- 首次扫描前完成命令和文件监听器注册，随后在后台执行索引。
- 索引期间允许搜索，展示当前已有端点并明确提示正在索引。
- 将每次文件解析视为完整替换，包括使用空结果清除旧端点。
- 在安全前提下合并 include 模式、对 watcher 事件应用排除规则、快速跳过不含受支持端点注解的文件，并将常规逐文件日志改为汇总日志。
- 使用有界堆替代有序数组 top-K 插入，同时保持现有排名语义与确定性顺序。
- 使用已配置的结果上限限制初始 QuickPick 数据量。
- Base URL 仅保存在内存中，通过 Spring 配置文件变更主动使缓存失效，避免每次命令都重新遍历目录。
- 为上述行为补充回归测试和性能导向测试。

## 能力

### 新增能力

- `responsive-endpoint-indexing`：后台、纯内存的端点索引，具备正确的文件替换语义并减少扫描工作。
- `scalable-endpoint-search`：有界的搜索与 QuickPick 结果构造，在保持现有排序的同时适应大型端点集合。
- `base-url-cache-invalidation`：进程内 Base URL 缓存，以及相关 Spring 配置文件变化时的主动失效。

### 修改能力

无。仓库当前没有基线能力规格。

## 影响范围

- 运行时影响：扩展激活、`FileScanner`、`FileWatcher`、`EndpointCache`、`SearchUI`、`BaseUrlResolver`、`ConfigManager` 及扫描日志。
- 测试影响：扫描器、缓存与搜索、可测试的 UI 行为、Base URL 解析器和扩展激活编排。
- 不改变公共命令 ID、配置键、端点解析语义、持久化数据格式或外部依赖。
- 扩展继续采用纯内存模式，每次 VS Code Extension Host 重启后都会重新全量扫描。
