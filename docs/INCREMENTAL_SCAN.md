# 增量扫描优化说明

## 功能概述

RestfulToolkit 使用**纯内存扫描状态**：每次 Extension Host 启动都会后台全量扫描，同一会话内的手动增量刷新只处理发生变化的文件。命令会在首次扫描前注册，因此扫描不会阻塞扩展使用。

## 工作原理

### 传统扫描方式
- 每次启动项目都扫描所有匹配的 Java/Kotlin 文件
- 每次刷新都清空缓存重新扫描
- **问题**：大型项目（如 1000+ 文件）启动耗时长

### 当前扫描优化
1. **后台首次扫描**：命令和 watcher 注册后，全量扫描匹配文件
2. **会话内增量刷新**：对比内存记录中的 `mtime + size`，任一元数据变化都会重新解析
3. **单次文件发现**：多个 include glob 合并为一次 `findFiles` 查询
4. **注解预筛选**：不含受支持 REST 注解的普通源文件不进入完整解析器
5. **原子整体替换**：解析前后 `mtime + size` 保持一致时才同时提交端点与扫描状态；解析为空时也会清除该文件的旧端点
6. **可恢复失败**：读取或解析失败不更新扫描时间，后续增量扫描仍会重试
7. **串行强制刷新**：扫描期间的全量刷新请求在当前轮结束后执行；当前轮失败时也会继续，并在新一轮开始前清理旧索引
8. **统一状态记录**：工作区扫描和 watcher 防抖扫描共用前后元数据校验；扫描中再次变化的文件不覆盖缓存并保留重试资格，删除文件同步清理端点和扫描状态

## 扫描策略

### 启动扫描
- **每次 Extension Host 启动**：后台全量扫描，不读取本地扫描缓存
- **扫描期间**：搜索可展示当前已经发现的端点；扫描结束后按 QuickPick 当前查询刷新，无端点时显示空索引提示
- **扩展停用**：释放配置订阅、停止安排新工作、清理扫描定时器，并等待配置重载与任意当前扫描安全收束

### 手动刷新
提供两种刷新模式：

#### 1. 增量刷新（推荐）
- 仅扫描修改过的文件
- 快速、高效
- 适合日常使用

#### 2. 全量刷新
- 重新扫描所有文件
- 完整、彻底
- 适合以下场景：
  - 配置变化（修改 `scanPaths`）
  - 怀疑缓存错误
  - 端点丢失或不准确
  - 项目结构重大调整

## 性能特征

- 首次扫描不再阻塞命令注册。
- 多个扫描模式只触发一次文件发现，重叠结果仍按标准化路径去重。
- 普通 Java/Kotlin 类只承担文件读取和廉价注解预筛选成本。
- 文件状态检查和解析均使用 15 并发上限。
- 扫描日志以汇总为主，不再为每个成功或未变化文件写日志。
- 实际耗时取决于工作区规模、磁盘或远程文件系统，文档不承诺固定百分比。

## 实时文件监听

增量扫描与文件监听器协同工作：
- **启动时**：后台全量扫描，搜索可使用当前部分结果
- **运行时**：文件监听器处理实时变化
- **状态同步**：watcher 扫描成功后更新同一份纯内存记录，文件删除时同步移除记录
- **手动刷新**：可选增量或全量

## 使用建议

1. **日常使用**：
   - 依赖自动增量扫描
   - 修改文件时自动更新（监听器）
   - 无需手动刷新

2. **配置变化后**：
   - 使用全量刷新
   - 确保 scanPaths 或 excludePaths 改变后重新扫描

3. **怀疑缓存错误**：
   - 使用全量刷新
   - 完全重建端点缓存

4. **大型项目**：
   - 通过 `scanPaths` 和 `excludePaths` 缩小扫描范围
   - 搜索结果数量通过 `maxResults` 控制

## 技术实现

### 核心模块
- `ScanStateManager`：会话内扫描状态管理器（纯内存）
- `FileScanner`：文件扫描器（支持增量）
- `FileWatcher`：按绝对路径及所属工作区相对路径应用排除规则，并处理创建、修改、删除事件

### 状态生命周期
- 扫描记录与端点索引只存在于 Extension Host 内存中
- 不使用 `workspaceState`，不创建本地索引文件
- Extension Host 重启后重新全量扫描
- 配置热重载与手动全量刷新不会和正在运行的扫描并行写入索引
- 单文件解析结果先暂存，只有解析前后 `mtime + size` 一致时才与扫描状态一起提交；不一致时保留原缓存
- 每轮扫描开始前取消上一轮状态栏隐藏计划，避免旧定时器隐藏新进度
- 不计算内容 hash；watcher 事件保证常规编辑实时重扫，`mtime + size` 用于会话内手动增量刷新，避免为全部文件增加读取和哈希成本

## 兼容性

- ✅ 向后兼容（无历史记录时自动全量扫描）
- ✅ 跨平台（Windows、Mac、Linux）
- ✅ 多工作区支持
- ✅ 单模块和多模块项目

## 未来优化方向

1. **性能观测**：在真实大型本地与远程工作区记录扫描阶段耗时
2. **智能扫描优先级**：优先处理活跃编辑文件
3. **并发自适应**：根据本地或远程文件系统调整并发度

---

**边界说明**：本功能刻意不持久化端点索引；性能优化集中在后台执行和减少无效工作。
