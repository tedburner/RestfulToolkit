## ADDED Requirements

### Requirement: 首次索引期间命令可用
扩展必须（MUST）在启动首次工作区扫描前注册全部贡献命令，并且该扫描不得阻塞扩展激活完成。

#### Scenario: 扩展在大型工作区激活
- **WHEN** 首次端点索引仍在运行
- **THEN** 所有贡献命令均已注册并可调用

#### Scenario: 后台扫描失败
- **WHEN** 首次后台扫描意外失败
- **THEN** 扩展记录失败，且不产生未处理的 Promise rejection

### Requirement: 搜索展示索引进行状态
搜索界面必须（MUST）在索引期间保持可用，并区分“正在索引但当前为空”和“索引完成后仍为空”。

#### Scenario: 尚无端点时打开搜索
- **WHEN** 索引正在进行且缓存为空
- **THEN** 打开带索引提示的空搜索选择器，而不是显示索引完成后的无端点警告

#### Scenario: 用户在索引期间搜索
- **WHEN** 索引正在进行且用户修改搜索条件
- **THEN** 使用内存中当前已有端点执行搜索

#### Scenario: 索引完成后缓存为空
- **WHEN** 索引已经结束且端点缓存为空
- **THEN** 显示现有的无端点警告

#### Scenario: 已打开搜索时索引完成
- **WHEN** 用户在索引期间保持搜索选择器打开，随后索引完成
- **THEN** 按当前查询刷新选择器；若缓存仍为空，则关闭选择器并显示无端点警告

#### Scenario: 索引在状态订阅建立前完成
- **WHEN** 索引恰好在搜索界面首次读取状态与注册状态监听器之间完成
- **THEN** 搜索界面复查当前状态并应用完成结果，不得永久保留 busy 或陈旧条目

### Requirement: 文件索引采用完整替换语义
每次成功读取文件后，必须（MUST）使用新解析的端点列表替换该文件的全部缓存端点，包括空列表。

#### Scenario: 受监听文件删除最后一个端点
- **WHEN** 原本包含端点的文件被修改为不再包含任何受支持端点注解
- **THEN** 删除该文件的全部缓存端点

#### Scenario: 文件端点发生变化
- **WHEN** 受监听文件解析出不同的端点集合
- **THEN** 该文件只保留本次新解析的端点

### Requirement: 工作区扫描避免无效源文件工作
工作区扫描必须（MUST）在枚举 include 模式时避免重复源文件候选；watcher 触发的扫描必须遵守排除配置；文件不可能包含受支持端点注解时，不得执行完整注解解析。

#### Scenario: 多个扫描模式重叠
- **WHEN** 两个扫描模式匹配同一个源文件
- **THEN** 工作区扫描期间该文件只索引一次

#### Scenario: 被排除的源文件发生变化
- **WHEN** 受监听路径命中配置的排除模式
- **THEN** 不为该路径安排防抖文件扫描

#### Scenario: 工作区相对排除模式
- **WHEN** `module/build/**` 这类排除模式匹配文件在所属工作区中的相对路径
- **THEN** watcher 不分发该文件的创建、修改或删除事件

#### Scenario: 普通源文件不含端点注解
- **WHEN** 匹配的 Java 或 Kotlin 文件不含任何受支持 Spring MVC 或 JAX-RS 注解名称
- **THEN** 使用空结果替换该文件缓存，且不调用完整注解解析器

### Requirement: 扫描诊断输出有界
正常工作区扫描必须（MUST）记录生命周期汇总和失败信息，不得为每个未修改或成功处理的文件输出常规消息。

#### Scenario: 大型扫描成功完成
- **WHEN** 数千个文件被无错误地处理
- **THEN** 日志包含扫描汇总，而不是每个文件一条成功或状态记录消息

### Requirement: 并发刷新与扫描失败保持索引可恢复
扫描进行期间收到强制全量刷新时，扫描器必须（MUST）在当前扫描结束后使用最新配置执行完整的新一轮扫描。文件读取或解析失败不得（MUST NOT）记录为成功扫描。

#### Scenario: 扫描期间配置发生变化
- **WHEN** 当前扫描尚未完成且配置变更触发强制全量刷新
- **THEN** 当前扫描结束后清理旧索引，并使用最新配置执行新一轮全量扫描

#### Scenario: 文件读取暂时失败
- **WHEN** 文件读取或解析抛出错误
- **THEN** 不更新该文件的扫描时间，使后续增量扫描能够重试

### Requirement: 后台扫描遵守扩展生命周期
扩展停用时必须（MUST）停止安排新的扫描工作、清理扫描器定时器，并等待已启动的后台扫描安全收束后再释放其依赖。

#### Scenario: 首次后台扫描期间停用扩展
- **WHEN** Extension Host 在首次扫描完成前停用扩展
- **THEN** 扫描不再更新已释放的 UI 或单例，并且停用流程等待扫描 Promise 安全结束

#### Scenario: 配置重载期间停用扩展
- **WHEN** 配置重载仍在读取项目配置时停用扩展
- **THEN** 停用流程等待该任务收束，且任务不得在停用后重建 watcher 或启动扫描

#### Scenario: 后续扫描期间停用扩展
- **WHEN** 首次扫描已结束，但手动或配置刷新扫描仍在运行
- **THEN** 停用流程等待当前扫描安全结束后再重置依赖

#### Scenario: 当前扫描失败且强制刷新已排队
- **WHEN** 当前扫描失败前已经收到强制全量刷新请求
- **THEN** 扫描器继续执行排队刷新，并使用最新配置重建索引

#### Scenario: 连续扫描更新状态栏
- **WHEN** 一轮扫描结束后立即开始排队的下一轮扫描
- **THEN** 前一轮的延迟隐藏任务不得隐藏后一轮的扫描进度
