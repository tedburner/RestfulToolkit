## Context

端点解析目前以类块字符串为单位协调 Spring MVC 与 JAX-RS 解析。类块包含其所有嵌套类，类级路径解析又会搜索整个类块中的第一个路径注解，因此方法级路径可能被当作类级路径，嵌套类端点也会被外层和内层重复解析。Spring 方法名查找还依赖固定 500 字符窗口。扫描侧分别维护端点缓存和内存扫描记录，但 watcher 只更新前者。Base URL 的生产命令已经使用异步路径，同步解析链仅被未使用的兼容入口和测试保留。

约束是保持 Java/Kotlin、Spring/JAX-RS、多路径、源码顺序、精确行号和内存模式等既有契约，不引入 AST 依赖、本地持久化、内容 hash 或新配置项。

## Goals / Non-Goals

**Goals:**

- 类级路径只来源于紧邻当前类声明的注解区域。
- 每个类只解析自己直接拥有的方法，嵌套类独立解析。
- 方法声明查找不受固定字符窗口限制，并且不会把后续注解参数误认为方法。
- 全文件只构建一次行索引，解析器使用绝对字符偏移计算行号。
- 任意成功扫描和文件删除都同步内存扫描记录，增量刷新按真实 `mtime + size` 判断。
- 生产与测试统一使用异步 Base URL 解析，watcher 只覆盖受支持的资源目录。

**Non-Goals:**

- 不引入 Java/Kotlin AST、语言服务器或新依赖。
- 不改变端点搜索评分、排序、缓存持久化策略和用户配置格式。
- 不实现继承路由、属性占位符、配置类路由等已知限制。
- 不把扫描并发和进度节流暴露为配置，也不改造 `EndpointCache.allEndpoints` 数据结构。

## Decisions

### 1. 先收集类范围，再按所有权生成解析视图

`AnnotationParser` 在净化文本上先收集所有类/接口的声明位置和花括号范围。每个类解析时，将其后代类的声明与类体替换为空格但保留换行，使外层解析器看不到内层端点；内层类仍使用自己的范围单独解析。

类块起点从当前类声明所在行开始，并只向前吸收完整的纯注解/注释/空白区域，不再把“以 `@` 开头但同时包含方法声明”的上一行误认为类注解。

替代方案是只解析顶层类，但会破坏现有嵌套控制器支持；引入 AST 则超出当前扩展的轻量定位。

### 2. 类路径以类型声明为硬边界

Spring 与 JAX-RS 的类级路径解析只检查当前类声明之前的注解区域。方法级扫描遇到位于类型声明之前的 `@RequestMapping` 时直接跳过，不再使用 300/1000 字符启发式窗口。

### 3. 方法声明使用结构扫描而非字符窗口

Spring 解析器在与原文等长的净化文本上，从 mapping 注解末尾开始跳过空白和完整后续注解，然后寻找声明中的首个参数左括号，并从其前方提取方法标识符。扫描以类边界、成员结束符和方法体起始符为停止条件，因此不会跨成员关联。

### 4. 行号统一使用文件级索引与绝对偏移

`AnnotationParser` 仅对完整文件构建一次行索引。Spring/JAX-RS 解析器接收类视图在文件中的字符偏移，使用 `offset + annotationIndex` 查询绝对行号；直接单元测试仍可使用默认偏移 0。

### 5. 成功扫描是缓存与状态的共同提交点

`FileScanner` 提供内部“扫描并记录”路径，工作区扫描和防抖 watcher 均复用它。端点缓存更新成功后读取当前文件 stat，并记录 `mtime`、`size`、端点数和扫描时间；文件删除同时清理缓存、定时器和状态记录。

增量判断在 `mtime` 或 `size` 任一不相等时重扫。内容 hash 会要求读取所有表面未变化的文件，抵消增量扫描收益，因此不采用。

### 6. Base URL 只保留异步 I/O

删除 `ConfigManager.getBaseUrl()`、`BaseUrlResolver.resolve()` 及同步目录遍历/读取方法，将测试和脚本迁移到 `resolveAsync()`。配置 watcher 使用 `**/main/resources/{application,application-*,bootstrap}.{yml,yaml,properties}`，与 Resolver 的发现规则一致；不误用 watcher 的布尔事件忽略参数。

## Risks / Trade-offs

- [类范围遮罩错误可能漏掉合法外层方法] → 用顶层多类、嵌套类、同一行注解和多行类注解集成测试覆盖所有权。
- [结构扫描可能把后续注解参数识别为方法] → 显式跳过带/不带参数的完整注解，并添加多注解和超长声明测试。
- [stat 与文件读取之间存在竞态] → 在成功读取解析后获取 stat；后续文件事件仍会触发再次扫描，失败时不写成功状态。
- [删除同步 Base URL 影响测试脚本] → 先迁移所有仓库内调用点，再通过 TypeScript 测试与 URL/cURL 自动化脚本验证。
- [收窄 watcher 可能遗漏非标准目录] → Resolver 本身只读取父目录名为 `main` 的 `resources`，因此 watcher 与现有功能范围保持一致。

## Migration Plan

1. 先添加能够复现当前解析错误和状态漂移的失败测试。
2. 分别实现解析器、扫描状态和 Base URL 变更，每批运行相关测试。
3. 运行完整 `npm test`、参数复制、全文件、URL/cURL 自动化脚本。
4. 同步项目文档；若出现回归，可按模块独立回退，不涉及数据迁移。
